## 二、问题 1：手动输入改成"可选择 + 不用手打"

**原实现**（`app.py`）：在线取数面板下面无条件摊开一块 120 高的输入框
「粘贴补充的财报摘要（可留空）」。虽然文案写着"可选"，但视觉上像必经步骤，
用户会以为必须手打内容才能开始分析。

**新实现**：改为三选一（默认第一项，页面不再出现空的输入框）：

| 选项 | 行为 |
|---|---|
| 🟢 不追加（推荐） | 不显示输入框；提示「本次分析完全使用在线取数结果，无需任何手动输入」 |
| ⚡ 一键用在线数据生成摘要 | 出现「⬇️ 生成并填入摘要」按钮，点击后用当前在线数据自动生成精简摘要并填入（**零打字**），填完仍可编辑 |
| ✍️ 手动粘贴自定义内容 | 保留原手写框，供粘贴业绩说明会纪要 / 研报结论 / 自有 Excel |

**一键摘要长什么样**（`_build_online_digest()`）：
只取「最近一个年报」的指标明细 + 最近 3 期速览，实测约 229 字 —— 是"能直接改"的体量，
而不是把整段取数原文再贴一遍（那样只是重复送进模型，白白烧 token）。

**回归断言**：默认项为「不追加」、默认不渲染手填框、点按钮后 `single_text` 含最新年报指标
且长度 < 1500 字。

## 三、问题 2：证据核对满屏误报（根因 + 修法）

**截图现象**（中国中免 601888）：

```
证据核对：指标「2025年报经营活动现金流净额」= 60.59 未能在原始数据中找到对应数值
证据核对：图表项「2025年报营业成本」= 361.09 未能在原始数据中找到对应数值
证据核对：图表项「2025年报销售费用」= 86.84 未能在原始数据中找到对应数值
证据核对：图表项「2025年报管理费用」= 22.04 未能在原始数据中找到对应数值
```

**根因是两处，叠加才变成满屏黄条：**

1. **证据库不完整**。`verify_evidence` 只拿 `raw_data`（在线取数摘要）当证据库，
   而营业成本 / 销售费用 / 管理费用 / 经营活动现金流净额这些数字出自**年报原文**
   （RAG 检索片段或解析出的 PDF 全文），根本不在取数摘要里 —— 于是有明确出处的数字
   被一律判成"模型推算"。
2. **单位口径不同**。提示词要求模型统一输出**亿元**，而年报原表以**元**列示：
   `60.59`（亿元）对应的原文是 `6,058,908,000`（元）。原实现对"数字是否出现"只做
   字符串包含，**必然对不上**。

**修法：**

- `verify_evidence(..., extra_sources=[...])`：页面把 **`single_pdftext`（年报解析全文，
  ≤4 MB）** 与**当次 RAG 检索片段**一起作为证据文本传入。
- 新增 `_extract_numbers()`（正则抽数字 + 内容指纹缓存最近 4 份文本，避免几十万字年报反复重扫）
  与 `number_has_source()`：三道关任一通过即算有据 ——
  ① 原文直配（含千分位、去尾零写法）；
  ② **单位链换算**（亿元 ↔ 元/千元/万元/十万元/百万元，双向）；
  ③ 舍入容差（相对 1.5e-3，至少 0.005），吸收"6,058,908,000 → 60.59"这类两位小数截断。
  数值比对走二分查找（`bisect`），避免 6 万个数 × 11 个量纲的线性扫描。
- **UI 降噪**：核对结果不再一条一个黄条地刷屏，改为一条可折叠面板
  「🔎 证据核对：N 条提示（点击展开）」；全部通过时显示一行
  「✅ 证据核对通过：指标与图表数值均可在取数摘要 / 年报检索片段中找到出处」。

**关键点：检查的有效性没有被削弱** —— 编造的数字（如 99999 亿元）依然会被揪出，
只是不再把"单位换算过的真数"当成假数。回归断言覆盖了三种情形：
有年报原文时不误报（0 条）、无年报原文时仍报警（≥1 条）、编造数值仍报警（≥1 条）。

## 四、问题 3：报告期数缺 5 和 7

**根因**（`app.py`）：选项是写死的 `[1, 2, 3, 4, 6, 8]`。当时只是随手挑了几个值，
没有业务含义，但用户看到"1 2 3 4 6 8"会直接怀疑功能有缺陷。

**修法**：
- 选项改为 `list(range(1, 9))` → 1~8 连续。
- 补 `help` 气泡 + 页内说明，明确它到底干什么：

  > **报告期数 = 抓取最近 N 期财务数据**（含季报/中报/年报）；它只影响
  > 「可选报告的期数」与趋势范围。**评分与图表固定按「最近一个年报」口径计算**，
  > 换 N 不会让分数漂移。

  这句"固定年报口径"很关键：评分链路本来就做了 `annual_only=True` + 兜底，
  说清这一点，用户才不会怀疑"改期数会不会把分数改掉"。
