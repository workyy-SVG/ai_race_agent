## P1-01 年度时间轴：从"一张柱状图"改成"可查多年"

### 清单原文要求

> 年度时间轴要支持年份范围筛选；点击年份看当年数据；能切换指标（营收/净利润/ROE/毛利率）；
> 显示同比和数据来源；缺失年份不要填 0，要明确列出缺哪一年；比率变化用百分点而不是百分比；能导出 CSV。

### 改了什么

| 清单要求 | 实现位置 | 具体做法 |
|---|---|---|
| 年份范围筛选 | `app.py:1755 render_year_timeline()` | `select_slider` 双端拉选，只列出**真正有年报数据**的年份端点 |
| 点击年份看当年数据 | 同上 | 加 `timeline_year` 选择器，选中年份后 4 张 `st.metric` 卡片同步换数 |
| 指标切换 | `_TIMELINE_METRICS` | 营业收入 / 净利润 / ROE / 毛利率 四项，`radio` 切换即重绘 |
| 同比 + 数据来源 | `render_year_timeline()` 明细表 | 每行带 `report_date` / `report_type`，缺这类字段时标"—"而不是编 |
| **缺失年份不填 0** | 同上 | 缺 2022 就明确写「缺失年份：2022（不补零，图中不画占位柱）」 |
| **比率用百分点** | `_TIMELINE_METRICS` 的 `_is_ratio` 标记 | ROE / 毛利率同比显示 `+2.00 pp`；营收/净利润显示 `+14.3%` |
| 导出 CSV | 明细表下方 | `st.download_button` 导出该指标全序列 |

### 为什么"缺年不补零"必须单独做

东财接口返回的年报序列，遇到退市整理、借壳、会计年度调整时会**整年缺席**。
如果按常见做法给缺失年份画一根 0 柱，读者会误读成"那年公司营收归零"——这是财务图表里最严重的误导之一，比留空坏得多。

### 为什么比率必须走 pp

ROE 从 12% 涨到 14%：

- 写成"增长 16.7%" —— 严格说是相对变化率，容易被当成增速指标，跟营收增速混为一谈
- 写成 "+2.00 pp" —— 一目了然是绝对差值

同一张表里两种口径并列时尤其重要，系统在指标定义处用 `_is_ratio` 一次性锁死，不会漏。

## P1-02 多公司对比：从"写死 2 家"改成"2~5 家动态增删"

### 清单原文要求

> 用户能自己决定对比几家（2~5 家）；动态增加/移除输入区；要检查重复公司、无效代码、未完成输入；
> 移除公司后表格、图表、报告要同步更新。

### 改了什么

1. **数量自由**：`cmp_n` 会话计数 + `➕ / ➖` 按钮，2 家起步、**5 家封顶**，到边界按钮自动 `disabled`（不会点了没反应）。
2. **移除即清干净**：每家一套 `#1/#2/#3` 标签的动态 key，移除走 `_panel_clear()` 清理派生状态。

   > ⚠️ **踩过的坑**：不能 `st.session_state.pop(控件key)` —— 控件一经实例化，pop 它的 key 会直接抛
   > `StreamlitAPIException`。正确做法是清**业务派生状态**（对比结果、图表缓存），控件本身的 key 交给 Streamlit 管。
3. **三类拦截**（缺一不可，否则用户会拿到一份"看起来对但其实少一家"的报告）：
   - 重复公司 → 明确报错 **并禁用分析按钮**（不是只给个警告让你照样跑出一份错报告）
   - 无效代码 → 单独标出是哪一家
   - 未完成输入 → 指出第 N 家还没取到数据
4. **图表支持 N 家**：新增 `fig_compare_group_n()`（分组柱状）与 `fig_compare_dims_n()`（维度雷达/柱状），
   配色轮换表 `_CMP_SERIES_COLORS`（深蓝 / 资本金 / 青 / 紫 / 棕，均通过对比度核查）。

   > **缺项不画 0**：某公司没有 `debt_ratio` 时，柱顶写 `N/A`，**不画一根 0 柱冒充 0% 负债率**——和 P1-01 同一条原则。

## P1-03 对比口径：默认对齐共同年报年份

### 清单原文要求

> 默认对齐共同年报年份；程序生成比较表与差额；各公司独立设置行业；支持 CSV 与报告导出；
> 没有共同年份时要明确提示，不同年度不能混着比。

### 改了什么

1. **对齐基准**：对 N 家各自的有数据年报年份求**交集**，作为默认对比年份；用户在 `cmp_base_year` 里可以改，但改不了"必须在交集里"这件事。
2. **各公司独立行业**：每家一个 `_cmp_industry_select()`。

   > ⚠️ **踩过的坑**：带 `key` 的 `st.selectbox` 的 `index` 参数是**失效**的。
   > 想让它跟着数据自动切换，必须显式写 `st.session_state[key] = 目标值`。
3. **无共同年份 → 明确报错**：直接提示「无共同年报年份」，而不是静默拿不同年度凑一张表。这是清单里"不同年度不混比"的兜底。
4. **对照表与导出**：N 家横向表新增**「极差」列**（一眼看出最大分歧在哪），`st.download_button` 导出 CSV 与报告。

### 口径为什么这么严

把 A 家 2024 年报和 B 家 2022 年报放一起比 ROE，差值里混了两年宏观环境差异，这个差值没有解释力。
宁可报"没法比"，也不给一个有解释力的假象。

## P1-04 行业评分适配：把"金融"拆成银行 / 保险 / 证券

### 清单原文要求

> 拆分银行/保险/证券的适用指标；加入行业基准倍数（近似同行对标）；行业变化必须真实影响指标与评价依据；
> 跨行业的分数不作排名依据。

### 改了什么（`scoring.py`）

1. **三套维度表**：`_DIM_BANK` / `_DIM_INSURER` / `_DIM_SECURITIES`（保留 `_DIM_FINANCE = _DIM_BANK` 兼容旧引用）。
   - 银行：不良率 / 核心一级资本充足率 / 拨备覆盖率
   - 保险：偿付能力充足率 / 新业务价值率
   - 证券：ROE + 净利率权重拉高，杠杆用专属表
2. **自动判定**：`detect_finance_kind(metrics, industry)` —— **按"真的拿得到哪些指标"判定**，不靠猜行业名：

   ```python
   if 有 solvency_ar 或 nbv_rate:        return "保险"
   if 有 npl_ratio / core_car / provision_coverage: return "银行"
   if industry == "金融":                 return "证券"
   ```
3. **券商专属杠杆表** `_DEBT_TABLE_SECURITIES`：券商负债率 78% 属正常经营（客户保证金沉淀），按通用表会被打成 <4 分的"高风险"，这是**典型的行业误判**。
4. **同行对标措辞** `_peer_multiple()`：输出「约为行业 ROE 优秀线的 **X 倍**」。

   > ⚠️ **严禁写成"同行前 X%"** —— 我们手里没有全行业分位数数据，写百分比等于编造一个不存在的口径。
   > 倍数是从行业基准线直接算出来的，可复算。
5. **UI 可干预**：单公司分析页加了「🤖 自动识别 / 🏦 银行 / 🛡️ 保险 / 📈 证券」选择器，覆盖自动判定结果；非金融行业时置空。
6. **跨行业不排名**：多公司对比在跨行业时输出 `cross_industry=True`，表格上方明确警告"不同行业基准不同，分数不可直接排序"。

## P1-05 结论与引用核验：从"抽查"改成"可正向定位"

### 清单原文要求

> 数值 → 页码/原文的证据卡；RAG 检索排序改混合重排；证据不足时要明确说明，不能假装引用有效。

### 改了什么

#### ① 证据卡 `evidence_map()`（`analysis_validate.py:455`）

**关键差异：正向映射，不是反向抽查。**

- 旧做法：正文里写了"第 42 页"，就去 42 页看看有没有东西 —— 无法发现"数值编造得不离谱但页码写错"。
- 新做法：**每个待核数值 → 年报页码 + 原文片段**，优先级：

  ```
  年报检索片段（带页码）  >  在线取数摘要  >  显式标注"未定位"
  ```

定位链支持**单位换算**：模型写 `60.59 亿元`、年报写 `6,058,908,000.00 元` —— 通过 `_UNIT_SCALES` 11 档 + `bisect` 容差区间匹配（`_REL_TOL = 1.5e-3`），仍能命中。

> **踩过的坑**：匹配用的候选字符串**必须包含带千分位的写法**。
> 取数摘要和年报里几乎都写 `1,741.00 亿元`，而模型输出的是 `1741`；
> 只比无分隔符字符串，会让明明有出处的数字被判成"推算"。已在 `number_has_source()` 里补齐 `f"{_v:,.0f}"` / `f"{_v:,.1f}"`。

#### ② 混合重排（`rag_engine.py:512`）

```python
RERANK_KEYWORD_WEIGHT = 0.25
最终相关度 = (1 - w) × 余弦相似度 + w × 关键词重叠率
```

- 中文按 **2-gram** 切词，英文/数字按 token
- 候选取 `top_k × 3` 再重排，避免第一轮就把正确答案筛掉
- 返回字段同时给出 `score`（混合值）与 `cos`（纯语义），便于灰度对比

**为什么需要关键词**：纯向量检索对"拨备覆盖率"这类术语的召回不稳定——语义相近但字面不同，反过来也成立。加一路字面重叠能显著拉回报告原文。

#### ③ 页码引用正确率 `citation_accuracy()`（`analysis_validate.py:515`）

统计正文「第 X 页」落在**真实页数范围内**的比例。**页码越界即便数值命中也判失败** —— 引用串页就是引用失效，不能因为数字碰巧对上就放过。

#### ④ 证据不足的明确表述

页面新增「🔗 证据卡」区块，显示 `N/M 项数值可定位到年报原文`；
**一项都定位不到时**，明确写「证据不足，无法判断，建议先解析该年报 PDF」，而不是给出一张空白表格让观众以为"都通过了"。

## 仍然办不到的（不建议在答辩里含糊其辞）

1. **同行对标是"基准线倍数"，不是真实分位数。** 手里没有全行业分布数据，措辞必须写"约为行业优秀线的 X 倍"，不能写"行业前 X%"。
2. **指标覆盖率依赖第三方接口字段。** 东财财务指标接口一旦调整字段名或返回口径，覆盖率会突然下降。
   页面已用「覆盖率 + 置信度」如实暴露，覆盖率不足时**不给总分**——宁可说"评不了"，也不硬凑一个数。
3. **银行/保险的专属指标并非每家公司都齐。** 拿不到不良率、拨备覆盖率时，`detect_finance_kind()` 会退成
   "无法判定"，此时建议在 UI 里手动指定子行业（已提供选择器）。
3. **离线评测用的是固定桩数据**，它证明的是"链路算得对、算得一致"，**不能证明"数值与真实财报一致"** —— 后者仍需人工逐项核对官方年报。
4. **RAG 只在索引已存在时生效**，评测脚本不自动建库（建库产生 Embedding 费用，线上是"用户下载年报时顺带建库"）。
