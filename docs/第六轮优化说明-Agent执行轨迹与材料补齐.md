### 2. 新增「Agent 执行轨迹」（本轮重点）

**为什么是重点**：赛题是「让 **AI Agent** 赋能千行百业」。原作品能力很强，
但页面上呈现的**全是结果** —— 评委看不到它"调了什么工具、按什么顺序、
失败了怎么换路"。而"会不会自己判断"，正是 Agent 与普通脚本的分水岭。

**实现**：

| 层 | 文件 | 说明 |
|---|---|---|
| 记录层 | `agent_trace.py`（新增） | `Tracer` + `span()` 上下文管理器；纯 Python、不依赖 Streamlit、可单测。记录每步的 步骤号/阶段/动作/输入/产出/耗时/状态/备注 |
| 插桩层 | `app.py` | 在**真实调用点**埋点，不是事后写描述：`llm_once()`（全站唯一模型出口）、在线取数落库函数、`_rag_retrieve()`、`analyze_core()` 之后回填评分/校验/证据/引用 |
| 展示层 | `app.py` 第 5 个页签 | 「🤖 Agent 轨迹」：4 张统计卡（工具调用 / 自主决策 / 自检环节 / 降级·失败）+ 完整台账表 + 自主决策点表 + 链路说明 |
| 材料层 | PPT 第 18 页（新增） | 六步调用链表 + 自主决策点，与页面一一对应 |

**状态语义**（刻意区分，不把问题藏起来）：
- ✅ 成功 —— 正常完成
- 🟡 降级 —— Agent 自己换了条路但仍有产出（如模型名回退、无年报记录退回最近报告期）
- ❌ 失败 —— 这一步确实没做成
- ⚪ 跳过 —— 条件不满足，**如实记一步"未执行"**（比如没建年报索引时不假装检索过）

**关键设计**：台账里每个数字都取自 `_core` / 调用返回值本身，与页面显示**同源**，
不存在"页面显示一套、轨迹记录另一套"。观测层任何异常都不影响业务结果。

**自主决策点**（这几处是"Agent 味"最浓的地方）：
1. **口径锁定** —— 自动识别并排除中期报告，只用年报口径（中期为年初至今累计值）
2. **行业识别** —— 按公司名匹配财务基准库，未命中退回通用四维框架并如实标注
3. **故障自愈** —— 模型名不可用自动回退兼容名、接口失败自动降级，全程显式告知
