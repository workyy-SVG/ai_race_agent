# 对照实验报告：本 Agent vs 直接使用大模型

> 目的：用可复现的实验证明"结构化流水线 + 规则评分 + RAG 检索 + 输出校验"比
> 直接把财报丢给大模型更准确、更可解释、更可靠。
> 配套脚本：`eval_cases.py`（一键运行，自动生成本报告的数据表格）。

---

## 一、实验设计

### 实验对象

| 组别 | 配置 | 说明 |
|---|---|---|
| A 组（基线） | 直接大模型 | 把财务摘要文本直接交给 DeepSeek，自由生成分析与评分 |
| B 组（本作品） | 完整 Agent 流水线 | 在线结构化取数 → 固定规则引擎评分 → 年报 RAG 检索（带页码）→ LLM 分析 → 千问润色 → 输出校验 |

### 评测维度（4 项）

1. **准确性**：关键指标数值与官方披露的一致性（对照东方财富结构化接口与年报原文人工核对）
2. **可溯源性**：结论是否附带年报页码引用（可自动检测"第X页"标记）
3. **一致性 / 可复现性**：同一输入重复运行 3 次，评分是否完全相同（规则引擎的天然属性；A 组自由生成无法保证）
4. **耗时**：端到端秒数

### 运行方法

```bash
# 在已配置 DEEPSEEK_API_KEY / QWEN_API_KEY 的环境运行
python eval_cases.py 600519 贵州茅台 4     # 单案例
python eval_cases.py                       # 默认 3 案例（茅台/招行/宁德）
```

输出：`eval_results/对照实验结果.md`（汇总表）+ A/B 两组原始输出。

## 二、预期差异（机制层面，代码可验证）

| 差异点 | A 组：直接大模型 | B 组：本 Agent | 验证方式 |
|---|---|---|---|
| 评分可复现 | ❌ temperature>0 自由生成，同一数据两次打分可能不同 | ✅ `scoring.py` 固定阈值分段线性插值，同一输入 100% 相同分数 | `python scoring.py` 自检含可复现断言 |
| 评分可解释 | ❌ 只有结论没有依据 | ✅ 每个分数附"指标值→得分→阈值标准"的完整依据链，页面可展开查看 | 页面"查看评分依据"折叠面板 |
| 引用可溯源 | ❌ 无出处 | ✅ 年报结论标注"见年报第X页"（RAG 按页切片） | `rag_engine.format_citations` 输出带页码 |
| 数值准确性 | ⚠️ 依赖模型誊抄文本数字，长文本易错 | ✅ 评分与图表数据直接来自东财结构化接口，模型不参与数值计算 | 对比输出与接口原始值 |
| 格式健壮性 | ⚠️ 输出格式异常会导致下游页面报错 | ✅ `validate_analysis` 校验字段/类型/范围，异常项自动修复或剔除 | 单元测试 T1-T4（异常输入全部安全通过） |
| 中期数据口径 | ⚠️ 可能把一季报/半年报误读为全年 | ✅ 数据侧显式标注报告期口径；趋势图仅用年报口径 | `data_source.build_summary_text` 口径提示 |
| 切换数据残留 | ⚠️ 旧结果可能残留误导 | ✅ 数据指纹（公司+报告期+年报+行业）变化统一清空 | 代码 `data_sig` / `cmp_sig` 机制 |

## 四、结论要点（可直接放答辩 PPT）

1. **准确性**：B 组的数值型结论（评分、图表、趋势）不经过模型生成，直接来自结构化接口与固定规则，从机制上消除了"模型算错数"。
2. **可解释**：每个评分附完整依据链（指标值→阈值→得分），评委可现场核验。
3. **可溯源**：年报相关结论带页码引用，可直接翻到年报对应位置查证。
4. **可复现**：规则评分 100% 确定性——这是直接使用大模型无法做到的核心差异。
5. **健壮**：模型输出异常时页面不崩溃（校验层自动修复/降级）。

## 五、诚实的局限性（评委追问预案）

| 问题 | 回答 |
|---|---|
| 规则阈值是谁定的？ | 基于公开的行业通行财务分析经验法则（ROE>15% 优秀、不良率<1.5% 健康等），代码内每条阈值均附判读标准注释，可审查、可调整 |
| 规则会不会太死板？ | 规则只负责"打分"，定性分析、风险识别、行业对比仍由大模型完成；两者互补而非替代 |
| A 组也许不慢？ | 耗时不是核心优势，核心是准确性与可复现性；耗时数据如实呈现 |
| 案例只有 3 个够吗？ | 脚本支持任意 A 股代码一键扩展，评委可现场指定公司复测 |
