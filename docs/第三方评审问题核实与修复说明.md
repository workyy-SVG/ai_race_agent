## 1. 确实存在并已修复（15 条）

### 1.1 默认模型名存在兼容性风险（报告 3.1）★最高优先级

**报告说得对，且比它描述的更严重。** 经联网核实 DeepSeek 官方公告：
`deepseek-chat` / `deepseek-reasoner` 已于 **2026-07-24 15:59 UTC 正式停用**，
现役名为 `deepseek-v4-flash`（快）/ `deepseek-v4-pro`（强）。

原代码把 `deepseek-chat` 写死在默认值里 → 对演示型项目等于
**「评委点一下分析 → 页面弹 Model Not Exist」的致命事故**。

**修法**（`app.py`）：
- 默认值改为 `deepseek-v4-flash`
- 新增 `_MODEL_FALLBACKS` 三级候选链 + `_model_candidates()` 去重
- 新增 `_is_model_error()`：**只有"模型名类"错误才换名重试**（限流/鉴权换名毫无意义）
- `json_mode` 先试 `response_format={"type":"json_object"}`，服务端不支持时裸调同名模型
- **流式已输出部分内容后不再换名重试**，否则新模型会把内容重讲一遍
- 额度只在逻辑调用开始时计一次，重试不重复扣

### 1.2 手动模式可能使用上一次在线公司的评分和证据（3.2）

**确认存在。** 评分调用点无条件读取 `single_online_code`，导致"先查在线 A 公司、再手动粘贴 B 公司文本"
时，评分仍去请求 A 的财务指标。

**修法**：新增 `_is_online = src_mode.startswith("🌐")`，非在线模式不再读该键；
在线取数改用 `annual_only=True` 统一取年报口径。

### 1.3 数据内容变化不会可靠清除旧结论（3.3）

**确认存在。** `_data_sig()` / `_cmp_sig()` 只哈希"参数"（代码、行业、期数），不含正文，
所以把同一只股票的手动文本从 ROE 5% 改成 20%，指纹不变、旧结论继续复用。

**修法**：新增 `_content_hash(raw_data)`（MD5 短哈希）并并入两处指纹。

### 1.4 不同报告可能误复用同一个年报索引（3.4）★

**确认存在。** 原判据是 `existing >= len(norm)` 就复用集合 —— 同一年报的"修订版"、
或同年"半年报"，只要切块数不少就会直接复用旧向量。

**修法**（`rag_engine.py`）：
- `doc_tag_for(公告日期, 报告类型)` → 标签形如 `20260420_A`（年报）/ `20260820_H`（半年报）
- `_collection_name(code, year, doc_tag)` → 不同报告落到不同集合
- `_doc_fingerprint()`（MD5 抽样首尾块）与库中存档指纹比对，**不一致则 `delete_collection` 重建**
- `find_index_tag(code, year)` 走 `list_collections()`，兼容改动前已建好的历史索引

### 1.5 缺失数据可能呈现为满分综合评价（3.5）★

**确认存在。** 空维度被排除后对剩余维度取均值 —— "只填一个 ROE=20%"会拿到 `10.0` 的"综合分"。

**修法**：新增 `MIN_COVERAGE = 0.5` 门槛。覆盖率不足时 `total_score = None`，
`confidence = "信息不足"`，只展示可得维度分 + 缺失清单 + 说明。
复验：仅 ROE=20% → `total_score = null`，`coverage = 0.125`。

### 1.6 让行业适配进入评分规则（4.2）★

**确认存在。** `scoring.py` 只在"金融 / 通用"之间切换，其余行业共用一把尺子 ——
银行 ROE 11% 会被判成"瘦狗"。报告这条与项目既有的"同业对标"设计约定完全一致。

**修法**：`INDUSTRY_PROFILE` 成为 (ROE 优秀线, 营收增速稳健线) 的**唯一真源**；
以行业基准线为锚点，用 `tables_for_industry()` 缩放 ROE / 营收增速 / 净利增速三张打分表。
锚点系数刻意设计成"通用行业代回后与 v1 定点一致"（ROE 15%→9 分、20%→10 分），
**保证历史结论仍可复现**。

同时 `app.py` 的 `_INDUSTRY_BASE` 与四象限基准线改为直接读 `scoring.INDUSTRY_PROFILE`，
消除评分阈值 / 散点基准线 / 页面文案三处口径打架的可能。

**复验（同 ROE=11%）**：盈利能力分 通用 7.0 / 消费 5.9 / 新能源 8.4 / 医药 7.4 / 互联网 7.4 —— 四维得分不再相同。

### 1.7 从格式校验扩展到数值与引用验证（4.3）

**确认存在。** 原校验只做字段类型/范围兜底。

**修法**：新增 `verify_evidence(analysis, raw_data, page_range)`：
- **数值字面回溯**：指标明细与图表里的每个数值，必须能在原始数据文本中找到
  （容忍千分位 `1,234.56` 与舍入写法 `1234.6`）
- **页码越界检查**：正文引用的"第 X 页"若超出年报实际页数即判疑点
- 只报告、不改数 —— 摆出疑点由分析者判断

### 1.8 RAG 切片丢掉表格行 + 引用被截断（5.1）

**确认存在，且原实现很粗暴。** `_split_paragraphs` 把「长度 <20 全部丢弃」——
而财报里最关键的恰恰是短行：「营业收入 100.5 亿元」「资产负债率 42.3%」。
引用还固定截到前 280 字，落在后半段的结论直接消失。

**修法**：
- 保留含数字的短行；并**把紧邻在前的短标签行一起带上**，避免出现"只留下 100亿元、却不知道是谁的 100亿元"
- `CITATION_MAX_CHARS = 1200`（280 → 1200）
- 新增 `CHUNK_VERSION`，切片策略一变版本号即变，防止旧向量库被误复用

> 未做：扫描件 OCR 恢复路径。属新增能力而非缺陷，见 §4。

### 1.9 解耦 RAG 与润色开关（5.3）

**确认存在。** 建库 / 研报检索绑定在 `use_dual_model`（润色开关）上 ——
用户关掉润色后，证据使用行为会随入口变化。

**修法**：建库与检索与润色开关解耦，所有研究入口遵循同一证据策略。

### 1.10 统一双公司对比和单公司分析能力（6.3）

**确认存在。** 对比路径只把两份摘要和 PDF 开头拼起来丢给模型生成表格，
**没有复用规则评分、按页检索与结构化校验** —— 于是"单公司有 6.5 分的规则评分，对比页却只有模型口述"。

**修法**：新增 `_cmp_side_metrics()`，在对比页生成**两家公司的规则评分对照表**，
并在跨行业时给出显式警告（"两者评分基准不同，ROE 优秀线分别为 X% / Y%，不可直接比大小"）。

### 1.11 修正超时和限流处理（7.1）

**确认存在，报告描述准确。** Embedding 遇 429 只调用一次就抛错 ——
等于"一遇限流，整年报告索引全废"。

**修法**：`_embed_batch` 的 `_call_one` 对 **429 与 5xx** 增加退避重试（2s/4s）+ 随机扰动
（避免多路并发同时重试再次撞上限流）；`_embed_query` 同样重试；
`llm_qwen._call` 也补上 429/5xx 重试，不可重试错误则快速返回原文兜底。

### 1.12 按实际资源管理预算（7.2）

**确认存在两个问题**：① 计数只覆盖 DeepSeek 包装函数，千问与 Embedding 不在账本里；
② 计数用"读文件 → 加一 → 写回"，并发请求会互相覆盖丢计数。

**修法**：新增 `budget.py`：
- 分桶记账 `llm` / `polish` / `embed`，三类调用各有账本与限额
- `tempfile.mkstemp` + **`os.replace` 原子替换**，并发下不丢计数
- `rag_engine` 按批次数计入 embed 桶，`llm_qwen` 每次逻辑调用计入 polish 桶
- 侧边栏展示"今日用量：润色 N / 向量化 N 批"
- 纯文件实现、不依赖 Streamlit，任何异常静默吞掉（预算统计失败绝不拖垮主流程）
